**ADR-002: Windows engine profile vault**

Date: 2026-10-04. Status: implemented for the new engine catalog and Windows legacy state/snapshot persistence; the complete P1 acceptance gate remains open.

Use one authenticated encrypted snapshot for the complete new engine catalog, including profile metadata, credentials, optimistic revisions, and the future route selection. This is the single-envelope alternative explicitly allowed in section 5 of the implementation plan. Metadata and secrets cannot commit as different generations because there is only one snapshot.

The production protector uses Windows DPAPI in current-user scope, with UI forbidden and purpose-specific optional entropy. It never sets `CRYPTPROTECT_LOCAL_MACHINE`. Elevated workers receive session credentials over their authenticated IPC and do not decrypt the user's vault.

Location: `<configDir>/state-v2/engine-profiles.vault`. Windows global state now lives in `state-v2/desktop-state.vault`; subscription bodies are encrypted under `state-v2/subscriptions/`. Old desktop writers know `state.json` and the legacy cache directory. Their recreated files are never authoritative after migration. The legacy writer's actual serialization path has been exercised; executable downgrade acceptance has not yet been performed.

Before commit, protection is round-trip verified. Only ciphertext reaches the temporary file. The file is flushed and closed, then Windows `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)` replaces the previous snapshot. The containing directory has a protected inheritable DACL admitting only the exact app user and SYSTEM. Symlink/reparse-point storage is rejected. A failed replace leaves the previous snapshot and in-memory catalog intact. Corrupt data and purpose/key mismatch fail closed; no empty/default overwrite is attempted.

Public profile lists and change events use `Summary`, which contains no config. Full profile data is returned only by the explicit editor API. Save returns metadata, performs strict JSON/size/union validation, and requires a matching revision for updates/deletes. Selected profile deletion retains an unresolved reference; saving never selects or connects.

On non-Windows systems, this new protector is unavailable; there is no plaintext fallback for new engine profiles. Legacy persistence on those platforms remains unchanged. Windows production selects `NewPlatformStore` and fails closed on protected-state corruption. Reset takes the engine data and snapshot gates, reopens the catalog, and reloads protected state after file deletion so stale credentials cannot be saved back.

Verified: real Windows DPAPI round trip and purpose binding; directory ACL; tampering; replace failure; temp cleanup; editor isolation; concurrent stale revisions; API/event redaction; reset persistence; race detection for the new packages.

Windows migration commits the complete private state before making an encrypted initial recovery checkpoint and removing this app's legacy plaintext. Checkpoint/cleanup failure blocks startup/save; restart resumes from the committed vault. A missing main with an existing recovery checkpoint fails closed. Old temporary state/cache writes are archived as opaque encrypted recovery data. A separate encrypted completion checkpoint prevents reimport of old subscription caches, including resurrection of deleted bodies. Recovery snapshots are not automatically adopted. Legacy backup import writes protected state. See [migration evidence and limits](/E:/projects/WhiteVPN-Desktop/docs/implementation/LEGACY-VAULT-MIGRATION_FA.md).

The global PublicAppState/editor contract now redacts the defined credential/raw-config inventory across state JSON and nested results. Explicit editor APIs retain full data; node lists/events exclude share links and expose availability metadata. Custom DNS endpoints stay private during ordinary settings updates. URL-bearing text events/logs use a public guard. Default backup v2 omits credentials and restores unresolved placeholders; v1 imports remain supported. Failed restore cleans its newly created resolver files and preserves the previous committed snapshot. See [public state and backup evidence](/E:/projects/WhiteVPN-Desktop/docs/implementation/PUBLIC-STATE-BACKUP_FA.md).

Remaining P1 work: prove downgrade with an old binary, decide how global state plus engine selection joins the authoritative transaction, and extend the public backup to the separate new engine catalog. Full disk/power-loss fault acceptance and multi-process write coordination remain open. Arbitrary user exports and another application's import source are outside automatic plaintext cleanup. URL redaction is not a guarantee that every arbitrary log/message or user-written metadata field is free of secrets.
